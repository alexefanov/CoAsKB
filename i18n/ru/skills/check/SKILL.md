# /check

> Сканирование всей вики на проблемы здоровья: битые ссылки, отсутствующие обратные ссылки, устаревшие утверждения, дублирующиеся страницы, осиротевшие страницы, несоответствия схеме.

## Аргументы

- --full (опц.): глубокое сканирование (xref, орфография, осиротевшие). По умолч. — быстрая проверка.
- --fix (опц.): исправить найденные проблемы (через /edit). По умолч. — только отчёт.

## Область проверки

### 1. Инфраструктура сущностей (всегда)
- YAML-схема: все типы из entities.yaml имеют каталоги в wiki/
- Обязательные поля frontmatter: 
equired: true из entities.yaml
- Валидация значений: enum, range, date, link
- Разделы тела: по шаблонам templates/

### 2. Целостность графа (всегда)
- Типы рёбер валидны (из edges.yaml)
- Нет дубликатов (from, to, type)
- Вершины существуют
- confidence: high|medium|low (если требуется)

### 3. Симметрия xref (--full)
- Прямая ссылка A→B = обратная B→A по правилам xref.yaml

### 4. Битые ссылки (--full)
- [[slug]] → файл существует
- [text](path) → файл существует
- URL → проверка формата

### 5. Орфография (--full)
- Опечатки, грамматика
- «я/мы» в энциклопедическом тексте

### 6. Осиротевшие (--full)
- Страницы без входящих ссылок (исключая новые < 7 дней)

### 7. raw/ (--full)
- Файлы без записи в Source Notes

## Выход

Отчёт с категориями:
`
🔴 Критические: ...
🟡 Предупреждения: ...
🔵 Заметки: ...
📊 Сводка: N критических, M предупреждений, K заметок
`

## Процесс
1. Загрузить схему (runtime/schema/*.yaml)
2. Сканировать wiki/ — проверки шагов 1-5
3. Проверить граф — edges.jsonl
4. Проверить вики-ссылки (--full)
5. Собрать отчёт
6. Вывести результат (при --fix — запросить подтверждение)

## Ограничения
- Ничего не исправлять без --fix
- Не изменять raw/
- Не трогать .git/
